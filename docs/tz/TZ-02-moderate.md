# ТЗ-02: moderate.html — локальная страница модератора WAAM

**Статус:** к разработке (вариант Б, локальный кабинет модератора)
**Зависимость:** ТЗ-01 (формат `data/incoming/verified-*.json`)
**Стек:** чистый HTML + JS, один файл `moderate.html` в корне репозитория, без сборки и внешних библиотек. Открывается локально в браузере.

## 1. Назначение

Шаг 06 «Human moderation» пайплайна. Модератор просматривает проверенных кандидатов, выносит решение, и страница формирует обновлённые данные каталога. Ничего не отправляется в сеть — работа только с локальными файлами.

## 2. Загрузка данных

Два способа (оба реализовать):
1. **Кнопки-загрузчики** (`<input type="file">`): модератор выбирает файл `verified-*.json` и текущий `data/artworks.json`.
2. **File System Access API** (`showOpenFilePicker`, Chromium): выбор тех же файлов; если браузер не поддерживает — скрыть кнопку, остаётся способ 1.

После загрузки — сводка: всего кандидатов, вердикты (`pass/review/fail`).

## 3. Карточка кандидата

Поля отображения:
- Превью: по `preview_url` только как **внешняя ссылка** «Открыть источник» (полные изображения не встраивать — соответствие `rights_scope: link_only`). Если `rights_hint`/решение модератора допускает thumbnail — допускается `<img>` с внешним URL; по умолчанию выключено (переключатель «Показывать превью»).
- `title`, `creator`, `model_name`, `image_generator`, `source_url`
- Результат автопроверки: вердикт + список кодов причин (`verification.reasons`)
- `provenance_level`, `rights_status`, `rights_hint`, `third_party_ip_risk`, `source_jurisdiction`

## 4. Действия модератора (по кнопкам на карточке)

| Кнопка | Результат в паспорте |
|---|---|
| **Подтвердить (display)** | `rights_status=confirmed`, `rights_scope=display`, `status` готов к `published` |
| **Только ссылка** | `rights_status=external_link_only`, `rights_scope=link_only`, `status` готов к `published` |
| **Отклонить** | `rights_status=denied`, работа уходит в «Негативную коллекцию» (только ID + причина, без изображения) |
| **Отложить** | остаётся в incoming без изменений |

Обязательные элементы решения:
- Поле **«Основание прав (rights_basis)»** — URL или идентификатор документа. Без него кнопки «Подтвердить»/«Только ссылка» неактивны (RIGHTS_POLICY п.4).
- Выпадающий список **IP-риск**: `low/medium/high` (обязателен; `high` блокирует публикацию — кнопки подтверждения неактивны).
- Выпадающий список **юрисдикция** (ISO alpha-2 или `unknown`).
- Необязательный комментарий `reason`.

При решении в `history[]` паспорта добавляется: `{ event: "moderated", timestamp, actor: "moderator", reason: "<decision>: <comment>" }`.

## 5. Присвоение паспорта

- Подтверждённым работам присваивается `passport_id` формата `WAAM-<год>-<NNNN>` — следующий свободный номер после максимального в загруженном `artworks.json`. Номера удалённых работ **не переиспользуются**.
- `passport_version=1`, `created_at`/`updated_at` — текущее время UTC (ISO 8601).
- Перед включением в каталог — повторная проверка правил публикации из `PASSPORT_SCHEMA.json` (allOf): `provenance_level ∈ A/B`, `rights_status ∈ confirmed/external_link_only`, `third_party_ip_risk ∈ low/medium`, есть `rights_basis` и `content_hash`. Если `content_hash` пуст — предупреждение «публикация возможна только со scope link_only до появления хеша» (блокировать display).

## 6. Выгрузка результата

Кнопка **«Сохранить каталог»**:
1. Формирует обновлённый `artworks.json` (прежние работы + новые подтверждённые, со `status: "published"`).
2. Формирует `negative-collection.json` (отклонённые: `passport_id`/`external_id` + `reason`, без изображений).
3. Формирует строки для `ingestion_logs.jsonl` (решение по каждому кандидату).
4. Сохранение: через File System Access API — перезапись файлов на месте; иначе — три файла на скачивание с точными именами.
5. Исходный `verified-*.json` после сохранения предлагается переименовать в `<имя>.moderated` (инструкция на экране, если нет FS API).

## 7. Критерии приёмки

- Открывается как `file://` без сервера и без ошибок в консоли.
- Нельзя подтвердить работу без `rights_basis` и без выбранного IP-риска.
- `passport_id` продолжает нумерацию существующего каталога; дубликатов нет.
- Отклонённая работа не попадает в `artworks.json`, попадает в `negative-collection.json`.
- Каждое решение отражено в `history[]` паспорта и в `ingestion_logs.jsonl`.
- Никаких сетевых запросов, кроме открытия внешних ссылок по клику пользователя.

## 8. Ограничения

- Один файл, ванильный JS, без CDN (офлайн-работа).
- Интерфейс на русском; идентификаторы и значения полей — как в схеме (англ.).
- Данные не покидают компьютер; аналитика/трекеры запрещены.
